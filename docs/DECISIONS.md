## D-004 — 按实际到货拆分 MuSSE 开发主线

- **日期**：2026-11-02
- **状态**：当前路线，待后续验证调整
- **事实变化**：ESP32-S3 主板、面包板、跳线、按钮、Type-C 线及创乐博 16×16 I²C LED 矩阵已到手；麦克风、功放、扬声器、OLED 已采购但尚未到货。
- **决定**：M0 先验证 Windows USB、独立 ESP-IDF 串口与按钮程序；LED 矩阵先做 5V 供电与 I²C 兼容性调查，安全后再点亮；M1 等语音组件到货后使用经过核验的小智预编译固件；M2 再将 LED/按键正式整合到小智源码。
- **理由**：避免等待所有配件才开始，又不在电气参数未知时上电，也避免把测试固件误当最终小智固件。

- **重要风险**：矩阵明确标有 `+5V`，但其驱动芯片和 SDA/SCL 上拉电平未知；不能直接接 ESP32-S3 的 3.3V GPIO。
- **复查条件**：主板或矩阵实物型号得到确认、到货变更、厂家提供资料或出现更安全兼容的替代驱动。

## D-005 — M0 本地工具链与 Reasonix CLI 执行方式

- **日期**：2026-11-02
- **状态**：已采用（M0 期间）
- **背景**：ESP32-S3 位于用户另一台 Windows 电脑，用户不希望跨机器反复手动复制终端命令。
- **决定**：ChatGPT 负责按步骤制定任务、检查风险和验收；用户将提示词交给本机 Reasonix CLI 执行，再回传报告。**一次只做一个可验证步骤**，由用户转交下一任务；烧录、擦除、危险接线须逐次单独授权。ESP-IDF 选用 **v6.1 正式版**，与小智候选 v2.5.2 要求相符。先本地编译 Hello World，确认芯片安全状态和原 Flash 备份需求后才考虑首次烧录。
- **已报告结果**：EIM 0.20.1、ESP-IDF v6.1、本地 Hello World 构建成功；Flash 配置 16MB / DIO / 40MHz，尚未写入设备。上述是 Reasonix 提供的本机执行报告，未独立复验二进制文件；细节见 [TEST_LOG](TEST_LOG.md)。
- **风险与限制**：命令执行报告不等于板上固件运行；本地目录 `MuSSE-Lab` 不在公共仓库中。备份如包含设备个性化数据不得上传 Public 仓库。普通 ESP32 目标的教程固件不适配本板。
- **复查条件**：设备安全状态检测结果、首次烧录授权、后续小智版本变化。


## D-006 — 采用 USB 5V 长期有线桌面供电，暂不做电池

- **日期**：2026-11-02
- **状态**：已确认（覆盖当日早期“考虑 USB+电池双模式”的意向）
- **决定**：MuSSE 优先作为固定桌面机器人使用，使用可靠 USB 5V 电源；**当前不实现电池、充电、电池升压及自动切换系统**。正常开发仍使用已验证的主板 USB 连接。
- **理由**：无需移动需求，减少成本、电池充电热风险及复杂供电路径；有更多资源集中开发语音和表情。
- **边界**：用户图片中已购买带 14500 电池的供电模块，不意味着被选为正式电源；未经核验不得连接或充电。5V/3A 适配器为商品标称，不能推导整机够用。外部 5V/电脑 USB 反灌风险、外设电流仍待评估。
- **复查条件**：用户未来明确提出无线移动、供电瓶颈或实际功耗证据。

## D-007 — 区分已有 HT16K33A I²C 矩阵与新购 WS2812B RGB 矩阵

- **日期**：2026-11-02
- **状态**：硬件事实区分已采用；具体驱动/接线仍待核验
- **决定**：显示功能采用“16×16 逻辑帧/表情 → 可替换物理输出”的软件分层，暂不锁死其中一种矩阵。
- **已知**：已持有创乐博 I²C 16×16（2×HT16K33A），用户另购一块标称 5V、256 RGB WS2812B 的 16×16 具体模块；新采购仅商品图，尚未确认实物。两者通讯与电流模型截然不同。
- **安全**：BSS138 四路双向模块用于 I²C 电平转换的候选，**不默认适用于 WS2812B 时序数据**。两灯板都禁止未经电气核对直接上电/接 ESP32。
- **复查条件**：准确 SKU、到货实物、供电测试和最终选定主显示方式。

## D-009 — 优先复用官方小智 AI/情绪能力，MuSSE 自研限定于差异化层

- **状态**：已决定的软件开发方向，相关接口与平台能力仍待实测
- **背景**：用户注册并展示小智控制台 2.0：模型和记忆开关、知识库、内置服务、MCP 接入点、云端固件编译均有界面入口。固定 v2.5.2 源码已有 `Display::SetEmotion`、状态回调和单 LED 控制。
- **决定**：暂停原“从零独立重造整套表情系统”计划；第一轮仍实现 16×16 帧与离线可视化，但以**复用上游情绪语义、现成 AI/语音能力**为先，新增仅缺失的矩阵像素渲染、动画、状态桥接和后续物理输出适配。日常提醒、长期追踪和持久数据库延至 M3/M4，届时评估官方 MCP 扩展与现有任务管理工具的接口。

- **风险及限制**：所见平台能力仅为账号截图观察，记忆条目 0、MCP 状态显示加载中、设备未绑定；不得声称已获得可用云端工具或数据存储保证。实际修改上游、硬件烧录与接线需后续独立授权。

- **日期**：2026-11-03
- **状态**：产品范围已确认，尚未开发/部署
- **决定**：优先实现自有待办事项、长期目标、快捷记录、移动端/电脑网页以及学院 iWiki 知识库接入；不复用其他个人 Agent 项目的待办或历史档案。

- **取消/后置**：V1 不做主动推送、定时扫描、自动语音提醒、短信、微信推送等；用户打开网页或主动询问时才查看截止/逾期。
- **研发方式**：直接做正式可运行网页和业务逻辑；外部接口暂不可用时仅保留最低限度本地测试数据，不建立独立 Mock 阶段、不过度测试；基本数据正确性、权限和失败处理必须验证。
- **授权边界**：不擅自开通云服务、付费、部署或使用个人 iWiki Token；不得将凭证和个人记录写入公开仓库。
- **理由**：避开未到货硬件和主动推送的额外运维成本，把精力放在稳定可访问的个人任务/知识产品。
- **复查条件**：iWiki 真正支持的接口范围、腾讯云部署/备案与费用、未来用户重新提出主动提醒需求。

## D-013 — 采用 iWiki 单数据源与被动查询方案（覆盖原 V1 网页/CloudBase）

- **日期**：2026-11-03
- **状态**：用户已确认；取代 D-011 所描述的“独立网页 + CloudBase + 独立数据库” V1 实施方向（D-011 历史保留）
- **背景**：用户明确只需被动查询日程与逾期；学院 iWiki“我的知识库”可人工查看/编辑，并预留 Agent Token；不希望维护独立网页、云数据库或推送服务。
- **决定**：
  1. iWiki 是唯一持久化数据源；任务、日程、长期目标、进度、快捷记录均存 iWiki。
  2. 小智仅通过 MCP 读取/创建/更新，被动响应；不开发独立网页、CloudBase、云数据库、主动提醒或推送。
  3. 采用“小智接入点 ← 桥接客户端 → 本地 MCP Server → iWiki MCP”的最小方案；优先复用 `xiaozhi-client`（2.3.0，MIT），不自建持续服务器。
  4. 真实 iWiki 工具契约未确认前，适配器默认拒绝连接（`UNAVAILABLE`）；真实远程写入默认关闭，需独立开关且仅限授权联调。
  5. 数据模型采用人工可读 Markdown：任务状态只在任务总表；目标文档只引用任务 ID；进度由任务状态计算，并校验归属/重复/归档。
- **历史**：D-010（M1 显示核心归档）、D-011（B+C 方案）、D-012（5V/5A 采购）保留，不删除、不改写。
- **暂缓/取消**：Vue 网页、CloudBase、独立后端、主动提醒、推送、传统云服务器。
- **已知证据**：iWiki 官方公告（Markdown、冲突合并、权限、Token 预留）；SSE_MARKET 平台 MCP 文档（MCP 2025-06-18、Streamable HTTP、Bearer PAT，但属于论坛工具）；`xiaozhi-client` npm 元数据/README。iWiki 具体工具名/参数/版本条件写入**未公开**。
- **风险**：桥接单点（Windows 关机即失效）、iWiki 工具契约未知、WYSIWYG 可能改格式、Token 与权限管理、无官方托管桥接。
- **复查条件**：获得真实 iWiki 授权并完成 `initialize/tools/list` 联调；小智控制台直连第三方 MCP 能力确认；`xiaozhi-client` 版本/配置 schema 核对；用户改为需要主动提醒。
