- **状态**：已确认

## D-004 — 按实际到货拆分 MuSSE 开发主线

- **状态**：当前路线，待后续验证调整
- **事实变化**：ESP32-S3 主板、面包板、跳线、按钮、Type-C 线及创乐博 16×16 I²C LED 矩阵已到手；麦克风、功放、扬声器、OLED 已采购但尚未到货。
- **决定**：M0 先验证 Windows USB、独立 ESP-IDF 串口与按钮程序；LED 矩阵先做 5V 供电与 I²C 兼容性调查，安全后再点亮；M1 等语音组件到货后使用经过核验的小智预编译固件；M2 再将 LED/按键正式整合到小智源码。
- **理由**：避免等待所有配件才开始，又不在电气参数未知时上电，也避免把测试固件误当最终小智固件。
- **限制**：仅记录技术路线，不代表任何设备测试或刷写已获授权；独立 demo 固件与小智固件不会自动同时运行。
- **重要风险**：矩阵明确标有 `+5V`，但其驱动芯片和 SDA/SCL 上拉电平未知；不能直接接 ESP32-S3 的 3.3V GPIO。
- **复查条件**：主板或矩阵实物型号得到确认、到货变更、厂家提供资料或出现更安全兼容的替代驱动。

## D-005 — M0 本地工具链与 Reasonix CLI 执行方式

- **日期**：2026-11-02
- **状态**：已采用（M0 期间）
- **背景**：ESP32-S3 位于用户另一台 Windows 电脑，用户不希望跨机器反复手动复制终端命令。
- **决定**：ChatGPT 负责按步骤制定任务、检查风险和验收；用户将提示词交给本机 Reasonix CLI 执行，再回传报告。**一次只做一个可验证步骤**，由用户转交下一任务；烧录、擦除、危险接线须逐次单独授权。ESP-IDF 选用 **v6.1 正式版**，与小智候选 v2.5.2 要求相符。先本地编译 Hello World，确认芯片安全状态和原 Flash 备份需求后才考虑首次烧录。
- **已报告结果**：EIM 0.20.1、ESP-IDF v6.1、本地 Hello World 构建成功；Flash 配置 16MB / DIO / 40MHz，尚未写入设备。上述是 Reasonix 提供的本机执行报告，未独立复验二进制文件；细节见 [TEST_LOG](TEST_LOG.md)。
- **风险与限制**：命令执行报告不等于板上固件运行；本地目录 `MuSSE-Lab` 不在公共仓库中。备份如包含设备个性化数据不得上传 Public 仓库。普通 ESP32 目标的教程固件不适配本板。
- **复查条件**：设备安全状态检测结果、首次烧录授权、后续小智版本变化。


## D-006 — 采用 USB 5V 长期有线桌面供电，暂不做电池

- **日期**：2026-11-02
- **状态**：已确认（覆盖当日早期“考虑 USB+电池双模式”的意向）
- **决定**：MuSSE 优先作为固定桌面机器人使用，使用可靠 USB 5V 电源；**当前不实现电池、充电、电池升压及自动切换系统**。正常开发仍使用已验证的主板 USB 连接。
- **理由**：无需移动需求，减少成本、电池充电热风险及复杂供电路径；有更多资源集中开发语音和表情。
- **边界**：用户图片中已购买带 14500 电池的供电模块，不意味着被选为正式电源；未经核验不得连接或充电。5V/3A 适配器为商品标称，不能推导整机够用。外部 5V/电脑 USB 反灌风险、外设电流仍待评估。
- **复查条件**：用户未来明确提出无线移动、供电瓶颈或实际功耗证据。

## D-007 — 区分已有 HT16K33A I²C 矩阵与新购 WS2812B RGB 矩阵

- **日期**：2026-11-02
- **状态**：硬件事实区分已采用；具体驱动/接线仍待核验
- **决定**：显示功能采用“16×16 逻辑帧/表情 → 可替换物理输出”的软件分层，暂不锁死其中一种矩阵。
- **已知**：已持有创乐博 I²C 16×16（2×HT16K33A），用户另购一块标称 5V、256 RGB WS2812B 的 16×16 具体模块；新采购仅商品图，尚未确认实物。两者通讯与电流模型截然不同。
- **安全**：BSS138 四路双向模块用于 I²C 电平转换的候选，**不默认适用于 WS2812B 时序数据**。两灯板都禁止未经电气核对直接上电/接 ESP32。
- **复查条件**：准确 SKU、到货实物、供电测试和最终选定主显示方式。
