# 关键决策记录

每条记录保持：编号、日期、状态、背景、决定、理由和需要复查的条件。新决策用新编号追加，勿悄悄修改历史。

## D-001 — 独立主仓库与 Public

- **日期**：2026-11-02
- **状态**：已确认
- **决定**：使用 `Qi0331/MuSSE` 作为 MuSSE 的独立主仓库，按团队授权保持 Public。初期不把小智整个上游工程直接复制进来。
- **理由**：当前重点是硬件核验、过程记录及协作，避免引入尚未使用的庞大上游代码。
- **代价与风险**：公开提交可被他人查看和保留；未经脱敏的校园数据/密钥不得提交。未来需要修改固件时必须重新决策源码集成方式。
- **替代方案**：直接 Fork 小智，或将仓库设为 Private。

## D-002 — 先验证官方固件，再二次开发

- **日期**：2026-11-02
- **状态**：当前执行建议，待硬件确认
- **决定**：先核验实物和 USB 识别，确认兼容性后测试 `v2.5.2/bread-compact-wifi` 候选预编译固件；新功能再逐步引入源码开发。
- **理由**：减少初学阶段同时排查编译、接线、音频、联网的风险。
- **代价与风险**：候选固件可能不兼容实物，最终选择由测试决定。
- **替代方案**：直接从上游 ESP-IDF 源码构建。

## D-004 — 按实际到货拆分 MuSSE 开发主线

- **日期**：2026-11-02
- **状态**：当前路线，待后续验证调整
- **事实变化**：ESP32-S3 主板、面包板、跳线、按钮、Type-C 线及创乐博 16×16 I²C LED 矩阵已到手；麦克风、功放、扬声器、OLED 已采购但尚未到货。
- **决定**：M0 先验证 Windows USB、独立 ESP-IDF 串口与按钮程序；LED 矩阵先做 5V 供电与 I²C 兼容性调查，安全后再点亮；M1 等语音组件到货后使用经过核验的小智预编译固件；M2 再将 LED/按键正式整合到小智源码。
- **理由**：避免等待所有配件才开始，又不在电气参数未知时上电，也避免把测试固件误当最终小智固件。
- **限制**：仅记录技术路线，不代表任何设备测试或刷写已获授权；独立 demo 固件与小智固件不会自动同时运行。
- **重要风险**：矩阵明确标有 `+5V`，但其驱动芯片和 SDA/SCL 上拉电平未知；不能直接接 ESP32-S3 的 3.3V GPIO。
- **复查条件**：主板或矩阵实物型号得到确认、到货变更、厂家提供资料或出现更安全兼容的替代驱动。
