# MuSSE 分阶段开发路线（2026-11-02 根据到货情况调整）

> **路线原则：先完成可复现的最小实验，再逐个加入外设，最后集成上游小智语音固件和 MuSSE 后端。** 阶段的先后不是按硬件数量，而是按依赖和验证风险排的。所有“完成”须有 [TEST_LOG](TEST_LOG.md) 的实测记录，不能仅凭商品信息判断。

## M0 — 现在可以启动：单板基础开发（当前）

**已有**：ESP32-S3 N16R8、Type-C 数据线、面包板、跳线、按钮、创乐博 16×16 I²C LED 矩阵。**未到货**：麦克风、功放、喇叭、OLED。

### M0a：主板识别与工具链
- [ ] [#1](https://github.com/Qi0331/MuSSE/issues/1) 拍摄 ESP32-S3 实物正背面，验证板型、USB 接口、PCB/排针丝印。
- [ ] [#2](https://github.com/Qi0331/MuSSE/issues/2) **不接外设**：USB 连接 Windows，识别端口、驱动或 USB 设备；提交真实测试日志。
- [ ] 选定与候选小智源码相容的 ESP-IDF 开发环境；记录真实安装版本，不凭网上任意示例猜测。

### M0b：最小硬件程序
- [ ] [#10](https://github.com/Qi0331/MuSSE/issues/10) 创建独立 ESP-IDF 实验工程，串口可打印稳定的启动日志。
- [ ] 实物具备合适 LED/引脚时才验证 GPIO 输出。
- [ ] 按钮接入已核验输入 GPIO；验证按下/松开与软件消抖。
- [ ] 提交最小源码、版本、命令、测试证据到仓库（建议 `experiments/` 目录，任务执行时再创建）。

### M0c：LED 矩阵驱动**调查优先、接线后置**
- [ ] [#11](https://github.com/Qi0331/MuSSE/issues/11) 识别 LED 控制器、真实电源电压/电流、I²C 总线的上拉电压和设备地址。
- [ ] 如果确需 5V 供电且 SDA/SCL 有 5V 上拉，使用经确认的双向 I²C 电平转换器；禁止直接接 ESP32-S3 3.3V GPIO。
- [ ] 电气安全检查通过后，独立验证单像素 → 16×16 图案 → 简单状态动画，明确帧缓冲与像素映射。
- [ ] 初期不要假设现成小智预编译固件支持这块 LED 矩阵。

**M0 完成条件**：有串口、按钮实测记录；LED 模块至少完成**安全参数调查**。如果因缺少电平转换器或规格书不能安全接线，LED 点亮可延后，不影响 M1 语音主线。

## M1 — 语音配件到货后：小智原生语音闭环

- [ ] [#3](https://github.com/Qi0331/MuSSE/issues/3) 核验 INMP441、MAX98357、扬声器、OLED 的真实丝印、电压与参考 GPIO；避免短路和引脚冲突。
- [ ] [#4](https://github.com/Qi0331/MuSSE/issues/4) 核验固定上游版本 `78/xiaozhi-esp32 v2.5.2` 与候选 `bread-compact-wifi` 固件、发布包、烧录参数。
- [ ] 在负责人明确同意后刷入**小智固件**；按顺序完成启动 → 配网 → 绑定 → 收音 → 播放 → AI 问答。
- [ ] OLED 为辅助显示，不应让其阻塞语音核心验证；优先排查音频和网络链路。

**M1 完成条件**：可复现的一次完整“说话—听见回答”，有真实操作与日志。单板实验固件与小智固件互相替换，不能当作同时运行的功能。

## M2 — MuSSE 设备端整合

- [ ] 决定并固定上游源码集成方式与 commit，建立可重复构建的固件。
- [ ] 将通过实验的按钮、LED 矩阵驱动作为受控模块整合到小智设备端，必要时加入 MCP 设备控制工具。
- [ ] 核对 OLED 与 LED 矩阵是否能共用 I²C（地址、上拉电压、时序、总线负载）；不兼容时使用独立总线或电平转换。
- [ ] 使用状态机定义：待机 / 聆听 / 思考 / 播报 / 错误等对应灯效和按键。
- [ ] 确认设备能同时完成语音闭环和 LED 状态显示，记录性能、引脚与电源测试。

**M2 完成条件**：设备端固件可构建、可刷入、可测试；语音功能未被 LED/按键破坏。

## M3 — MuSSE 软件服务

- [ ] 确认软工集市、iWiki 等资料可访问的合法 API、权限范围与敏感数据边界。
- [ ] 实现最小授权检索/快速记录后端，设备端仅通过受控接口使用，密钥保存在服务端。
- [ ] 完成权限、脱敏、日志、失败回退和端到端测试。

## M4 — 记忆与主动提醒

- [ ] 明确记忆内容、存储位置、保留期限、用户同意与撤销机制。
- [ ] 设计待办调度、主动推送、离线重试、去重与通知失败处理。
- [ ] 验证持续运行与异常恢复；不将“模型会记住”当成持久存储能力。

## 软件路线选择

- **前期**用独立、尽量小的 **ESP-IDF** 实验（不是改小智全部源码）学习最少量 GPIO/I²C/串口；先验证工具链再编写功能。
- **语音阶段**用小智的匹配预编译固件，不要为验证语音就先造完整后端。
- **整合阶段**才修改小智源码；对来源锁定、修改清单和功能回归负责。
