# MuSSE 开发路线与里程碑

- **调整日期**：2026-11-02
- **制定依据**：团队目前仅收到 ESP32-S3 N16R8 开发板、面包板、跳线、按键、Type-C 线，以及一块创乐博（MAKEROBOT）16×16 I²C LED 矩阵；麦克风、功放、喇叭、OLED 等尚未到货。
- **策略**：**现有器件先做独立可验证的小实验；配件到齐再验证小智预编译语音；确认基线后再自定义整合。**
- **完成原则**：下述复选框只有在真实操作、可追溯日志/图片/代码及 `TEST_LOG.md` 存证后才可勾选。仓库文档/CI 通过不等于实体硬件已测通。

## 总览

| 顺序 | 阶段 | 本阶段硬件 | 做什么 | 通过的证据 |
| --- | --- | --- | --- | --- |
| A | **M0：板卡与最小程序（当前）** | 现有 ESP32-S3、Type-C | 核验实物、Windows USB 识别、最小串口打印 | 设备识别记录、固件构建/下载日志 |
| B | **M0：按钮输入（当前）** | 现有板、面包板、跳线、按钮 | 经核验的 GPIO + 上拉 + 消抖，串口上报点击 | 实际按键日志与最小例程 |
| C | **M0：矩阵调查（与 A/B 并行）** | 现有 16×16 LED 矩阵 | 确认驱动 IC、5V 供电、I²C 3.3V 兼容性/上拉与额定电流 | 原厂资料或板级可靠证据 |
| D | **M0：矩阵独立演示（有前置条件）** | 板、矩阵及必要电源/电平转换 | 仅在电气核验通过后：扫描 I²C、显示单点/表情 | 限亮测试、供电信息、日志 |
| E | **M1：小智语音闭环（等配件）** | 到货后音频模块和 OLED | 选兼容预编译固件，完成语音收发、联网和对话 | 实际录播与问答记录 |
| F | **M2：MuSSE 实体交互集成** | 全部确定兼容的模块 | 引入受控小智源码，集成矩阵/按键/屏幕、对话状态 | 可重复构建、完整连线图及集成测试 |
| G | **M3：知识检索与快捷记录** | 设备 + 服务端 | 授权接口验证，构建最小 MuSSE 后端 | 真实权限下的端到端检索/记录 |
| H | **M4：记忆与主动提醒** | 设备 + 服务端 | 持久化、调度、通知、离线恢复与权限管理 | 失败/重复/离线等场景验证 |

### M0-A｜核验开发板、USB 识别、首个程序

- [ ] [#1：ESP32-S3 开发板正反面、丝印与引脚核验](https://github.com/Qi0331/MuSSE/issues/1)
- [ ] [#2：不接外设，仅主板连接 Windows 的 USB 识别](https://github.com/Qi0331/MuSSE/issues/2)
- [ ] 在板型核验通过后选择开发环境。上游小智 v2.5.2 声明 ESP-IDF **最低 v6.0.1、推荐 v6.1**；如选其他版本须说明与未来整合的区别。
- [ ] 只烧录最小串口打印例程，确认稳定的编译、下载与串口输出；保留工具版本和日志。

**验收**：能明确回答「买的到底是哪块开发板、电脑能否识别、哪种方式可以烧入最小程序」。

### M0-B｜按钮输入

- [ ] [#7：按钮 GPIO 实验](https://github.com/Qi0331/MuSSE/issues/7)
- [ ] 经实物确认选择安全的引脚与上拉方式，断电接线。
- [ ] 实现按下/释放识别、消抖；记录按键日志。

**验收**：按一次、长按、连续按时，程序能稳定区分事件。不要求 OLED 或语音模块在场。

### M0-C｜矩阵模块核验和单独演示（**不可跳过安全门槛**）

- [ ] [#8：创乐博 16×16 LED 矩阵型号、驱动和供电/信号电平调查](https://github.com/Qi0331/MuSSE/issues/8)
- [ ] 取得高清正反面、驱动芯片丝印、数据手册/原理图；确认 SDA/SCL 的上拉电压、最大负载电流、3.3V 逻辑相容性。
- [ ] **只有完成上述核验、并准备必要电源/双向 I²C 电平转换后**，才开展 [#9：独立点亮与表情实验](https://github.com/Qi0331/MuSSE/issues/9)。

**强制安全边界**：矩阵接口标注 `+5V, GND, SDA, SCL`，不能直接断定 I²C 为 3.3V，也不能将 +5V 接至主板 3V3 引脚；本路线未批准未经核实的接线通电。

## 并行协作

- **硬件方向**：#1 / #2，之后 #7；另一路调查 #8，明确安全门槛后才进行 #9。
- **固件方向**：为 M1 做工具链准备及候选包核对，但在实物未核验之前不进行自动烧录。
- **服务方向**：可以调查校园 API 授权和后端架构，不代表已拥有访问权限。
- **项目管理**：[团队协作 #5](https://github.com/Qi0331/MuSSE/issues/5) 可独立进行。
