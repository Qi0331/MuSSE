# MuSSE 分阶段开发路线（2026-11-02 根据到货情况调整）

## 2026-11-02 晚间实际进度补充（以此更新下方早期计划复选框）

- **M0 已通过**：CH343/芯片通信、安全状态只读检查、16MiB 原 Flash 私有备份、授权烧录 ESP-IDF v6.1 Hello World 并观测 5 次真实启动/4 次软件复位。
- **M0 仍待**：具体 PCB/BOOT 引脚、按钮和 GPIO 真机、两种 LED 矩阵电气与供电；`gpio_button` 只有本地编译，**不是实测通过**。
- **M1 已做的软件准备**：上游 `v2.5.2/bread-compact-wifi` 固定源码研究与本地构建成功；尚未刷写、配网、绑定、录播音或验证 PSRAM。
- **新增另一种矩阵**：用户新购商品图为 5V WS2812B 16×16 RGB，与已持有的 2×HT16K33A I²C 矩阵不同；电源、电平、数据驱动需分开论证。
- **供电路线**：用户最终决定长期 USB 5V 桌面有线供电，暂不做电池。
- **下一段软件里程碑**：硬件无关 16×16 帧缓冲 → Idle/Listening/Thinking/Speaking/Error 5 表情 → 离线单元测试/可视化 → 上游状态接口适配评审，暂不接线/烧录。下方旧复选框未自动宣称全部完成。


> **路线原则：先完成可复现的最小实验，再逐个加入外设，最后集成上游小智语音固件和 MuSSE 后端。** 阶段的先后不是按硬件数量，而是按依赖和验证风险排的。所有“完成”须有 [TEST_LOG](TEST_LOG.md) 的实测记录，不能仅凭商品信息判断。

## M0 — 现在可以启动：单板基础开发（当前）

**已有**：ESP32-S3 N16R8、Type-C 数据线、面包板、跳线、按钮、创乐博 16×16 I²C LED 矩阵。**未到货**：麦克风、功放、喇叭、OLED。

### M0a：主板识别与工具链
- [ ] [#1](https://github.com/Qi0331/MuSSE/issues/1) 拍摄 ESP32-S3 实物正背面，验证板型、USB 接口、PCB/排针丝印。
- [x] [#2](https://github.com/Qi0331/MuSSE/issues/2) **不接外设**：用户完成 CH343 COM6 插拔对照与 ESP32-S3 只读识别；记录入 [TEST_LOG](TEST_LOG.md)。Issue 是否关闭仍按其完整验收条件判断。
- [x] 选定并安装 ESP-IDF **v6.1 正式版**（EIM 0.20.1，Reasonix 本地报告），符合小智上游 v2.5.2 的版本约束。

### M0b：最小硬件程序
- [x] **实际烧录与运行完成**：官方 ESP-IDF v6.1 Hello World（16MB / DIO / 40MHz，PSRAM 未启用）已由 Reasonix 报告成功烧录、串口输出及多次软件重启；**实验源码尚未提交本仓库**。
- [x] 首次烧录前只读检查 Secure Boot / Flash Encryption，完整备份 16MiB 原 Flash 并取得首次 Hello World 烧录单独授权。
- [x] [#10](https://github.com/Qi0331/MuSSE/issues/10) Hello World 真机稳定串口启动/自动重启；另有 GPIO/按钮独立工程本地编译，功能真机未验证。
- [ ] 实物具备合适 LED/引脚时才验证 GPIO 输出。
- [ ] 按钮接入已核验输入 GPIO；验证按下/松开与软件消抖。
- [ ] 提交最小源码、版本、命令、测试证据到仓库（建议 `experiments/` 目录，任务执行时再创建）。

### M0c：LED 矩阵驱动**调查优先、接线后置**
- [ ] [#11](https://github.com/Qi0331/MuSSE/issues/11) 识别 LED 控制器、真实电源电压/电流、I²C 总线的上拉电压和设备地址。
- [ ] 如果确需 5V 供电且 SDA/SCL 有 5V 上拉，使用经确认的双向 I²C 电平转换器；禁止直接接 ESP32-S3 3.3V GPIO。
- [ ] 电气安全检查通过后，独立验证单像素 → 16×16 图案 → 简单状态动画，明确帧缓冲与像素映射。
- [ ] 初期不要假设现成小智预编译固件支持这块 LED 矩阵。

**M0 完成条件**：有串口、按钮实测记录；LED 模块至少完成**安全参数调查**。如果因缺少电平转换器或规格书不能安全接线，LED 点亮可延后，不影响 M1 语音主线。

## M2 — MuSSE 设备端整合

- [ ] 决定并固定上游源码集成方式与 commit，建立可重复构建的固件。
- [ ] 将通过实验的按钮、LED 矩阵驱动作为受控模块整合到小智设备端，必要时加入 MCP 设备控制工具。

## 软件路线选择

- **前期**用独立、尽量小的 **ESP-IDF** 实验（不是改小智全部源码）学习最少量 GPIO/I²C/串口；先验证工具链再编写功能。
- **语音阶段**用小智的匹配预编译固件，不要为验证语音就先造完整后端。
- **整合阶段**才修改小智源码；对来源锁定、修改清单和功能回归负责。

## 2026-11-02 最新软件优先级补充（覆盖前文“直接独立新造表情系统”表述）

1. 先复核锁定小智 v2.5.2 的 `Display::SetEmotion`、`Application` 状态事件、LED 回调及真实 emotion 来源；原则是**复用现成的语音/情绪语义，MuSSE 只实现缺失的 16×16 逻辑帧和硬件适配接口**。
2. 一次离线批量完成 Windows 宿主 C++ 构建、5 类基本画面/动画、状态映射、单色/RGB 预览、确定性测试、孤立副本的上游最小补丁编译尝试和结果报告。不能把 Windows 测试或固件构建声称为真机运行。
3. 后续语音配件和 LED 到货、电平/电源核验、真实板卡兼容之后，再单独申请烧录/接线授权。M1 语音闭环和 M2 硬件整合验收条件不变。
4. 官方控制台已观察到记忆、知识库、扩展能力和 MCP 接入点；日常待办、定时提醒、长期进度与后台界面在后续 M3/M4 再决定存储/执行位置。详见 [官方平台调研](XIAOZHI_PLATFORM.md)。
