## 1. 已确定的产品/存储架构（不要再次讨论两固定文档方案）

```text
iWiki 个人空间/
└── MuSSE 个人管理/
    ├── 使用说明                  （可选；仅人工说明）
    ├── 任务总表                  （固定唯一任务文档；12 列 Markdown 表；唯一任务状态来源）
    ├── 快捷笔记                  （固定唯一文档；目前私人 notesDocId 映射未确认）
    ├── 长期目标索引              （可选人工导航，不作为状态数据库）
    ├── 长期目标/                 （受控的允许目录）
    │   ├── G-001                （目标文档，示例，不应虚构已创建）
    │   └── G-002                （目标文档，示例，不应虚构已创建）
    └── 历史归档                  （可选人工导航，不能代替 todo/done/archived 状态）
```

- 所有短期提醒和待办都放在同一个 `任务总表` 中，不为每项任务创建文档。固定 12 列列名/顺序：`ID,名称,说明,分类,优先级,状态,截止日期,截止时间,目标ID,阶段ID,创建时间,完成时间`，字段规则依 `software/musse-iwiki/src/markdown/tasks.ts`。
- 每个**长期目标**在 `长期目标/` 下有独立文档（`G-xxx`），阶段/说明/进度历史放目标文档；长期目标下面的具体待办仍放**同一任务总表**，按 `goalId + phaseId` 关联，避免双重状态源。目标解析/进度规则依 `src/markdown/goals.ts`。
- 核心文档 `任务总表`、`快捷笔记` 继续使用严格、固定 `doc_id` 映射；**长期目标拟采用“目录范围受限 + 动态查找 + 唯一性验证 + 用户二次确认”**，不要求用户每新增一个目标都手工把页面 ID 写到 Windows 文件。
- 当前 `createOfficialIwikiBestEffortPort` 和 S5 写入门禁仅接受 `tasks|notes`，目标 `goal_create/goal_update/goal_record_progress` 在 S5 **尚未实现**。单凭模型提示词或 iWiki 支持搜索，绝不声称目标写入已可用。
- “提醒”目前表示在表中存截止日期并在用户问时查询，**没有**常驻通知调度、到时主动发消息或后台监测。

## 3. 新 S6 子对话实施任务（建议一次完成软件能力，少做仪式性预检）

1. **先完成真实 iWiki 个人空间目录整理的指导/小范围核验**，确认现存《测试》旧页面 ID 能原位保留并移动，且原任务不丢；如果尚未移动，不要认为正式目录已存在。核心任务文档固定映射保留。
2. **只读发现接口契约**：复用已验证官方 `list_docs`/`list_doc_tree`/`read_doc` 和 iWiki 元数据，核对实得的目录/文档字段及分页/路径/父级 ID 的格式（历史 tools/list 只能证明工具存在，不证明每种响应结构）。避免用 `search_kb` 的模糊命中结果直接选择写入目标。
3. **实现可受控的长期目标动态发现**：用户仅指定一次可信的个人空间和 `长期目标` 目录作用域（可配置可信 folder/space anchor）；仅在该范围列出文档，按目标 ID + 精确标题/实际元数据唯一匹配；无匹配或重名、父目录不符、目标ID与正文不一致、歧义时失败关闭；读取页并检查 `parseGoal` 结构。用 `doc_id` 作为最终 edit/read 对象，而不是拿文档标题直接覆盖。
4. **实现目标创建与更新的 S5 式两轮语音协议**：新增 `goal_create`、`goal_update`、`goal_record_progress` 等明确白名单操作（实际范围视工具契约）；在预览中显示名称、目标 ID、阶段/任务关联、将写目标文档，下一轮用户明确确认后才调用官方受许可的创建/编辑工具，写后 `read_doc` 严格校验。创建要防重复目标 ID 和重名；若创建部分成功/回执不明，不可盲目重试。
5. **继续保证已有 S4/S5 任务链路回归**：原 `tasks` 的 prepare/confirm/cancel、一次写入/读回、日程查询、原有双 MCP 不变；处理可选 `notesDocId` 的配置而非凭空创建，避免扩展把真实任务总表写坏。
6. **实施最短现场验收**：先对 S6 长期目标做可验证的只读查找与预览/取消，再在用户明确授权的隔离目标/真实目标上测试一次有读回的创建或编辑；不准使用真实长期目标表做未授权破坏性探针。把用户报告和机器自动日志分开标注。
