# iWiki 数据模型与写入约束

## 1. 文档树

```text
MuSSE 个人管理/
  使用说明.md
  任务总表.md
  长期目标索引.md
  长期目标/
    G001.md
  快捷笔记.md
  历史归档.md
```

- 所有文档均为人工可读 Markdown。
- 任务状态**只**在 `任务总表.md` 中；目标文档仅保存任务 ID 引用。
- 不使用 JSON 数据库伪装成 Wiki；不使用第二套本地数据库或长期缓存。

## 2. 任务表

固定 12 列：

| 列 | 规则 |
|---|---|
| ID | 稳定唯一，`T-YYYYMMDD-XXXX`；同一 ID 不得复用 |
| 名称 | 非空 |
| 说明 | 可为空 |
| 分类 | 自由文本 |
| 优先级 | P0/P1/P2/P3 |
| 状态 | todo / done / archived |
| 截止日期 | `YYYY-MM-DD`（Asia/Shanghai） |
| 截止时间 | `HH:mm` 或空；空表示当天 23:59:59 到期 |
| 目标ID | 可空 |
| 阶段ID | 可空 |
| 创建时间 | `YYYY-MM-DD HH:mm` |
| 完成时间 | done 时必填；todo/archived 必须为空 |

- 单元格内的 `|` 必须转义为 `\|`。
- 表格结构损坏、ID 重复、日期非法时**解析失败**，不返回部分结果。
- 更新按 ID 定位，只替换该行；写后重新读取并校验其他任务未变化。

## 3. 长期目标

**S6 新规范（2026-11-05）：**正式目标编号采用 G001/G998（正则 ^G[0-9]{3,6}$），不带横线。历史真实 G-998/G-999 需要先按 docs/S6_GOAL_ID_MIGRATION_2026-11-05.md 迁移标题、正文和任务关联，才能运行新版 S6。历史完成验收记录仍按当时实际旧编号保留。

```markdown
# 目标：名称
- 目标ID: G001
- 说明: ...

## 阶段
### 阶段 P1：名称
- 阶段ID: P1
- 任务: T-..., T-...
- 手动进度: 文本

## 进度历史
| 日期 | 进度 | 说明 |
```

- 目标进度**按任务总表中的 `goalId + phaseId` 归属计算**，不依赖目标文档的 `任务:` 清单是否同步。
- 目标文档的 `任务:` 列表保留为人工阅读/诊断：
  - `missingTaskIds`：文档引用但任务表不存在；
  - `mismatchedTaskIds`：引用存在但任务归属其他目标/阶段；
  - `duplicateTaskIds`：文档重复引用；
  - `unlistedTaskIds`：任务表属于该目标但文档未列出；
  - `unassignedTaskIds`：任务表属于该目标但 `phaseId` 为空或未在文档声明。
- 进度分母排除 `archived`；阶段进度同样按任务表归属。
- `goal_record_progress` 只追加说明，百分比由任务状态计算，**不接受模型估算值**。
- 进度说明会规范化为单行，并对 `|` 与 `\` 转义/还原，避免表格注入和往返截断。
- 历史记录只追加，不覆盖。

## 4. 日期与逾期

- 固定 `Asia/Shanghai`（UTC+8，无夏令时）。
- 只有日期时，到期时间 = 当日 23:59:59.999。
- 逾期只针对 `todo`；`done` 与 `archived` 永不逾期。
- `schedule_today` 包含当天到期且未归档的任务；`upcoming` 只含未来 1..N 天的 todo。

## 5. 并发、版本与冲突

- 读取返回 `version`（本地夹具为内容 SHA-256 前 16 位；iWiki 使用其返回的版本/更新时间）。
- 写入尽量携带 `expectedVersion`。
- **写后必读**：内容不一致即报 `CONFLICT`，不报告成功。
- 写入工具返回 `isError=true` 时一律失败；即使读回内容恰好等于目标，也不报告成功。
- 写入工具必须返回明确成功标记（`confirmed`/`ok`/`success`），否则报 `IWIKI_WRITE_UNCONFIRMED`。
- **真实远程写入默认关闭**；只有显式 `MUSSE_ENABLE_REMOTE_IWIKI_WRITE=1`（且已获授权联调）才允许，`MUSSE_ALLOW_UNVERIFIED_IWIKI=1` 不会解除写保护。
- iWiki 若不提供版本条件写入，退化为“读 → 比对 → 写 → 读回验证”；无法检测的外部并发修改属于已知风险，必须报告。
- 权限错误、网络错误、MCP 不可用一律抛出，**绝不静默改本地存储**。

## 6. 富文本编辑的影响

iWiki 支持所见即所得编辑。它可能改变：

- 表格空格/对齐、空单元格写法；
- 标题层级、列表符号；
- 转义字符与换行。

解析器容忍空格与对齐差异，但要求固定列数和合法字段；结构被破坏时明确报错。写入后读回比对可发现内容变化；如需长期稳定，建议在 iWiki 中使用 Markdown 模式编辑这些文档。

## 7. 安全

- 不提供删除文档的工具。
- 只暴露任务/日程/目标/笔记的必要操作，不开放任意文档全文写入。
- 目标不明确时拒绝或要求确认，不猜测后覆盖。

## 8. S5 现场实证后确定的 S6 存储与动态发现方案（2026-11-04）

- S5 真实语音写入已由用户现场报告成功，当前私人 `taskDocId` 实际指向标题为《测试》的任务页面。该事实只证明已映射页面的读改写链路能使用，**不表示系统已经按名称自动查找并更换写入目标**。
- 任务总表与快捷笔记是唯一核心文档，长期保持受控静态 `doc_id` 映射（`notesDocId` 尚未确认）。用户应优先原位重命名/移动《测试》保留 ID 和任务；若新位置导致 ID 变化，须安全更新私人映射，不凭文档名盲写。
- 长期目标采用 `长期目标/` 目录，每个实际目标一文档、目标 ID 作为内部稳定身份；具体待办只写在任务总表，目标文档仅引用任务 ID 与阶段/进度说明。
- **S6 待实现**：可信个人空间/目录锚点内 `list_docs` / `list_doc_tree` 查找、唯一性与目标ID检查、受控创建/更新/进度记录及读回核对。不能用搜索相关度当成身份，也不能要求每个长期目标都硬编码 Windows 文档 ID。官方搜索/列表 API 存在但真实字段契约须先以只读方式验证。
- 这些目标写入能力不属于当前已上线的 S5；当前 S5 的 `S5Document` 仅为 `tasks | notes`。参见仓库 `docs/IWIKI_S6_DYNAMIC_DISCOVERY_HANDOFF.md` 与 `docs/DECISIONS.md` D-022。

## 9. S6 GitHub 首版代码状态（2026-11-04）

S6 目录发现及目标创建、更新、进度记录已在 `feat/iwiki-s6-document-discovery` 实现为**独立**的目标 MCP 与离线模拟测试，尚未在 Windows 安装，未编辑任何真实 iWiki 内容。`taskDocId` 与 `notesDocId` 仍按原有固定映射；目标文档的私人 ID 不登记进静态数组。目标必须位于经私有配置确认的 `spaceId + folderId`，标题规范为 `G-001` 等，正文 `目标ID` 与标题严格一致。

官方 `list_docs` 返回结构是否含父级、空间、完整分页与嵌套目录文档尚缺现场证据；代码按失败关闭设计，务必先运行新增只读结构诊断并据实核验，不得以 CI 通过冒充现场验收。具体见 `docs/IWIKI_S6_IMPLEMENTATION.md`。
