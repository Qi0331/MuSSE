# MuSSE Windows 本地 MCP 桥接复现包（草案）

> 状态：**仅供审核、隔离安装和假 Token 测试；尚未在全新 Windows 环境验收**。本目录不是新的 MCP Server，也不是 `software/musse-iwiki/` 的任务业务 MCP。当前已实测成功的生产方案及事实边界，以 [运行手册](../../docs/IWIKI_LOCAL_MCP_RUNBOOK.md)、[状态](../../docs/STATUS.md)、[测试记录](../../docs/TEST_LOG.md) 为准。

## 1. 本包要解决什么

MuSSE ESP32-S3 → 小智官方云端 MuSSE 智能体 → **Windows xiaozhi-client@2.3.0** → **iWiki 官方远程 MCP**（`https://ssemarket.cn/iwiki-api/mcp`）。

已经实测：小智 MCP 连接 1/1、iWiki 服务 1/1、`list_spaces` 真实读取成功、设备语音查询成功（用户确认）。尚未做到：新电脑完整复现、补丁自动安全应用、服务端只读权限拒写验证、长期稳定性与自动启动。

**本目录不包含**：真实接入点、Token、Windows 生产配置、私人 iWiki 资料、原始日志、完整 npm 包、固件或云端部署脚本。

## 2. 版本、运行条件与安全门槛

- Windows PowerShell、Node.js >= 22.18；已实测环境为 Node 22.23.2 / npm 10.9.8。
- 固定 `xiaozhi-client@2.3.0`；历史安装记录使用 `--ignore-scripts` 绕过可选音频依赖安装失败。此路径**仅验证 MCP 桥接**，不保证客户端自身音频完整。
- 新装的 `xiaozhi-client@2.3.0` 有已知风险：两处配置日志可能打印含 iWiki Authorization 的信息。本机生产环境已经针对已安装编译产物修复并以假令牌复测，但补丁**没有入仓库**。
- **先补丁、再假令牌测试、最后才考虑使用真实凭证**。静态检查工具不能替代假令牌动态验证。任何脚本均不得绕过用户对安装、启动、外部请求及真实资料访问的确认。
- 本地 Web UI 监听曾为 `0.0.0.0:9999`，需保留 TCP 9999 入站阻止规则。本地 `127.0.0.1:9999` 可访问不代表外部无法访问。

## 3. 文件与用途

| 路径 | 用途 | 对环境的影响 |
| --- | --- | --- |
| `config/xiaozhi.config.example.json` | **占位符**配置参考，严禁填入真实凭证后提交 | 无 |
| `scripts/Install-Isolated.ps1` | 检查条件；显式 `-Install` 才安装到独立沙箱前缀 | 默认只读；选择安装才写入**沙箱** |
| `scripts/Test-LocalBridge.ps1` | 只读检查安装产物中两处已知日志及防火墙规则 | 不启动、不修改、不读取私人配置 |
| `scripts/Start-AfterCanary.ps1` | 默认只说明安全条件；必须带显式参数才执行启动 | 仅在本地假令牌复测后使用 |
| `PATCH_HANDOFF.md` | 如何在本地安全地导出两处补丁差异与复测结果 | 不要求上传私有配置 |

## 4. 新 Windows 的安全重建顺序（非生产验收）

首先阅读根目录 [AGENTS.md](../../AGENTS.md) 和运行手册，并使用**非生产环境**：

```powershell
# 在本目录下（默认无副作用：仅检查，不安装）
.\scripts\Install-Isolated.ps1

# 明确选择后，才会把固定版本安装到一个独立沙箱
.\scripts\Install-Isolated.ps1 -Install

# 检查已安装的全局生产副本（只读；可能报告未修补）
.\scripts\Test-LocalBridge.ps1 -RequireFirewall
```

> 注意：独立沙箱新安装的是**未经本机补丁验证的第三方客户端**。**不得携带真实 Token 启动**。也不要对正在使用的全局 npm 包重复运行安装命令，以免覆盖修补。

接下来需从用户的 Windows 本地已修补产物导出**仅两处代码差异**，经脱敏审核后制定固定版本、精确匹配、可拒绝不兼容版本、可回滚的正式补丁。没有这一环节，本草案**不提供可验证的自动修补**。

在隔离环境以假接入点和假 iWiki Token 进行负向日志验证。确认没有完整假令牌出现在所有测试日志，并核实安装产物版本、入站防火墙规则、Web UI 工具启用范围及手动启动/停止行为后，才讨论真实账号联调。

启动保护脚本默认不会运行客户端；用 `-Start -CanaryPassed` 时会检查已知静态标志、防火墙并在**现有本地工作目录**调用 `xiaozhi start`。`-CanaryPassed` 是**用户对独立测试完成的确认**，脚本自身不能证明真实日志安全。

## 5. 生产环境：不做迁移

用户当前已成功的 Windows 环境，继续使用手册中的两条命令：

```powershell
Set-Location "$HOME\MuSSE-MCP-Local\musse-bridge"
xiaozhi start
```

**不要为本复现包重装、升级、覆盖或移动现有生产配置。** 本复现包目前不包含开机自启，不迁移腾讯云，不改 ESP32，不执行 iWiki 写入，也不连接 Muse 个人 Agent。
