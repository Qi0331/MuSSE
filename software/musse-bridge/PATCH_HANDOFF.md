# 安全补丁本地交接（待用户 Windows 验证）

## 背景

已实测的 `xiaozhi-client@2.3.0` 编译产物中，`dist/backend/WebServer.js` 和 `dist/backend/WebServerLauncher.js` 曾有将整个配置对象输出到日志的行为；假 Token 测试确认其中包含 iWiki Authorization。

用户 Windows 上这两处已修补，原文件存在本机 `.musse-original.bak` 备份，复测显示完整的两类假 Token 均未再出现。**上述修补文件与补丁脚本目前没有进入公共 GitHub**，不能从仅有的日志摘要可靠倒推出精确的字符串替换规则。

## 给本机 Reasonix 的后续工作（获得明确任务后才执行）

1. **仅读取**当前 `xiaozhi-client@2.3.0` 两个已修补 JS 文件及对应的 `.musse-original.bak`；核实安装版本和相对路径，不执行安装/升级、不修改原件。
2. 生成仅涉及这两个 JS 文件的**最小统一差异**，对原文、补丁及结果做脱敏扫描。不要包含私人配置、实际 Token、接入点 URL、用户名路径、设备标识或原始日志。
3. 记录两个文件补丁前后的**完整文件 SHA-256**（只有哈希值可以作为公开版本辨认辅助，不能代替人工审查）。
4. 仅回传脱敏差异、版本、必要结构信息及假 Token 的 `True/False` 结果，不要回传假令牌字符串、生产配置内容或真实知识库信息。
5. 待审核后再制作**精确匹配 + 不兼容拒绝 + 本机备份 + 可回滚**的补丁应用脚本，并在隔离安装中验证。绝不对当前已运行的生产安装直接应用新的实验性脚本。

## 安全验证边界

- 静态命中两处已知日志位置，只说明**已知风险点**的状态，不说明其他日志路径一定安全。
- 必须使用完全虚构的接入点/令牌验证；测试产生的日志也不进入 GitHub。
- 仅当假令牌未出现在日志、静态差异合理、工具开关与 TCP 9999 防火墙状态确认后，才能讨论真实只读凭证的受控恢复。
- 未经用户授权不验证写权限，不调用任何会改动 iWiki 数据的工具。

对第三方 npm 编译产物的手改只是临时处理。后续可考虑向原项目报告泄露位置并寻求正式修复，但报告本身也不得包含私人配置。
